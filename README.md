# Microsoft Entra ID Authentication with MSAL

## 1. Register the Application and API Scope
1. Go to Microsoft ENTRA ID -> Login with your Microsoft account -> App Registration -> New registration

2. During the creation you should include the following data:
- *Application name:* feel free to choose your own name
- *Supported accounts types:*
"Accounts in this organizational directory only (Microsoft only -  Single tenant)""
- *Redirect URI (Is used after successful authentication)*
Example: http://localhost:8080/auth/msal/callback
Must match exactly the value of AZURE_REDIRECT_URI in your .env file

3. Once you created the application, copy the following values from "General Information" Dashboard of your application.
Configure your .env file with the following variables:

AZURE_TENANT_ID=your_tenant_id
AZURE_CLIENT_ID=your_client_id
AZURE_CLIENT_SECRET=your_client_secret

4. Create custom API scope
This allows you to request an access token valid for your backend API because by default, Microsoft Entra ID issues tokens intended for Microsoft APIs such as Microsoft Graph.
Since your application needs to authenticate users against our own backend API, we must define a custom scope in the App Registration.

**To create a custom scope:*
Go to App Registration -> Expose an API -> Add a scope
Example scope name: access_as_user
The resulting scope identifier follows this format:
api://<APPLICATION_CLIENT_ID>/<SCOPE_NAME>
This endpoint is not an API endpoint we can "consume" is just a custom scope we created to tell Microsoft to generate tokens exclusively to authenticate users by our backend.

Copy this scope and save it in your .env file as
AZURE_SCOPE=api://[YOUR_CLIENT_ID]/access_as_user;

## 2. MSAL Client Configuration (msal.config.ts)
It is necessary to instantiate a ConfidentialClientApplication, which will handle all authentication flow securely.
With auth property we identify our application in Microsoft

## 3. Authentication Controllers
Instantiate ConfidentialClientApplication class using our MSAL Client Configuration to manage authentication flow.

1. Login Controller
- **getAuthCodeUrl()**
Generates the URL of the authorization request, letting the user input credentials and consent to the application.
Uses scopes and redirect URL as parameters to generate the login url.

**Example of generated URL:*
https://login.microsoftonline.com/{tenant}/oauth2/v2.0/authorize?
client_id=...
&scope=api://.../access_as_user
&redirect_uri=...
&response_type=code

2. Callback Controller
Handles the redirect after a successful login
- Obtains temporary `code` generated by Microsoft from query request
- Creates a token request with required properties, that Microsoft needs to verify before it gives us a token:
    - temporary code obtained from request query
    - scope
    - redirectUri

- **acquireTokenByCode()** : function that exchanges our tokenRequest for a token.
If a token was successfully generated, we return it to the client.

3. Me Controller
If a user is successfully authenticated and it doesn't exist in our database, create a registry of this user in our MSAL User Table.


## 4. Auth MSAL Service
Contains logic to decode and verify JWT emitted by Microsoft. We will use this logic in our custom Auth MSAL Hook.
1. Creates **jwksClient** that allows us to download Microsoft public keys.

2. **jwksUri** defines an URI where Microsoft publishes its public keys. Every Tenant has its own URL with public keys.

3. **getSignInKey()**
    - `kid` (Key ID): Identifies which specific key Microsoft used to sign the token
    - Downloads the corresponding public key
    - **key.getPublicKey()** returns it in a format usable by `jsonwebtoken`

4. **verifyMsalToken()**
    - receives a token in order to verify it
    - returns a Promise that resolves as an object with determined User properties
    - **jwt.decode(oken)** decodifies the given token
    - **getSignInKey()** get Microsoft's public key using the kid from token header
    - **jwt.verify** verifies token signature and claims (if it was emitted for our application and in our tenant)


## 5. Auth MSAL Hook
Our custom hook that implements Auth MSAL Service logic, and its used to protect routes, by including it in onRequest stage
**authenticateMsal()**
- obtains HTTP Authorization request header, clean it up to obtain only token part
- calls verifyMsalToken() function in order to verify it as described before
- attaches user info to request `request.user` (available in MeHandler)
